# 封面缩略图预览与排序设计

## 意图

用户选择多张封面后，可以快速确认图片内容、调整顺序，并明确哪一张会成为后续平台流程使用的主图。缩略图保持原始宽高比，不拉伸图片。

## 目标

- 在封面选择控件下显示紧凑的本地缩略图列表。
- 第一张显示“主图”，其余图片显示“PK”。
- 支持拖拽调整顺序；顺序变化立即反映到 `cover` 与 `pkCovers`。
- 支持移除单张图片，并在移除后重新计算主图与 PK 顺序。
- 缩略图使用 `object-fit: contain`，固定小卡片只提供背景和边界，不改变图片比例。
- 为键盘和无拖拽设备提供上移、下移操作。

## 非目标

- 不改变封面数量、格式、尺寸和平台适配规则。
- 不新增排序依赖，不改变 IndexedDB 资产协议。
- 不自动发布、保存草稿或替用户确认平台裁剪结果。

## 方案

考虑过引入第三方排序组件和使用原生 HTML 拖拽。第三方组件对最多 4 张图片的场景增加依赖和构建体积；采用原生拖拽即可满足当前需求，并保持 MV3 工作台简单。实现使用原生 `dragstart/dragover/drop` 事件，根据拖拽项和目标项计算新顺序。

## 交互与数据

选择图片后按文件选择顺序保存资产，界面将 `[cover, ...pkCovers]` 展平为列表。拖拽或上移/下移后重新拆分为第一项 `cover`、剩余项 `pkCovers`。删除最后一项时列表为空，清除主图和 PK 列表。拖拽过程中提供可见的目标态；按钮和图片具备可见焦点样式。

## 预览资源生命周期

组件根据资产 ID 读取对应的 Blob，并用 `URL.createObjectURL` 生成缩略图地址。资产列表变化或组件卸载时撤销旧 URL，避免持续占用内存。加载失败时保留文件名和操作控件，并显示简短提示。

## 验证

新增测试覆盖顺序拆分、拖拽排序和删除后的主图重选；运行 TypeScript 检查、Vitest、生产构建，并检查既有浏览器测试不受影响。
