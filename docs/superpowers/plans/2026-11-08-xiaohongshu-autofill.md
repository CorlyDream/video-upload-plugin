# 小红书封面与文案自动填写实施计划

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在现有扩展中增加可选单图封面、标题、正文、标签，完成后停留编辑页。
**Architecture:** 保留扩展 IndexedDB + 一次性桥接授权。批次保存文案与封面引用，任务冻结输入；小红书适配器等待实际上传完成、逐项写入和回读，异常交接人工。
**Tech Stack:** TypeScript、React、Manifest V3、Vitest、Playwright 本地夹具。
**Spec:** ../specs/2026-11-07-video-upload-plugin-design.md（M1 范围）

## Global Constraints
- 不发布、不存草稿，不填写声明，不覆盖已有文案，不自动重试视频。
- 无封面时保留平台默认封面；裁剪无法确认时提示人工处理。
- 真实内置浏览器上传不是扩展桥接验收；第二平台 M0 门槛仍未完成。用户明确要求继续开发 M1，本次实现作为实验能力，不宣称五站验证完成。
- 沿用当前功能分支和未提交实现，不额外移动或提交已有工作。

## Review Focus
- 同名/非图像封面和跨批次素材不得越权交接。
- 视频仍上传、上传失败时不得提前填写。
- 已有正文/重复控件、人工输入和停止操作不得被覆盖。
- 富文本、普通 #标签与平台结构化话题必须如实区分，不能把文本当作候选确认。
- 封面弹窗专用完成按钮与发布/存草稿绝不混用。

## Execution ledger
- 已核实真实 UI：标题 `input[placeholder="填写标题会有更多赞哦"]`，正文 `.tiptap.ProseMirror[contenteditable=true]`；封面 `.cover-plugin-preview` → `.cover-edit-entry` → `.cover-modal` 内 `input[aria-label="上传封面图片"]` 与 `.bottom-content` 的“完成”。
